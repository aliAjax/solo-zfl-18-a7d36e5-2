# 桌游联赛编排台

纯前端本地应用（无构建、无后端），把原来的规则卡片库扩成了桌游联赛编排台：管理**赛季、赛程、桌次、玩家与阵营**，所有数据存 localStorage。

直接用静态服务器打开 `index.html` 即可，例如：

```bash
npx http-server . -p 4173
# 或 python3 -m http.server 4173
```

## 功能与规则

### 分桌（`js/domain.js` · `seatRound`）
- 按人数自动规划桌容，**桌差不超过 1**，且不低于/超过赛季设定的每桌人数；
- **阵营互斥**：同阵营玩家不同桌；
- **熟练度均衡**：MRV + 回溯搜索，最小化各桌平均熟练度方差；
- **避免重复同桌**：已发布/已结算轮次里同过桌的组合不再同桌，无法满足时**阻断并给出原因**，不偷偷放宽；
- 人数失衡（如锁住第 3 桌但只剩 8 人、会出现 2 人桌）同样阻断；
- 首轮多解时带**一步前瞻**：优先选不会把下一轮组合锁死的布局（社交球手排程问题）。

### 出席、替换与锁座
- 迟到者暂不入座、到场后重排；缺席者移除；替补玩家替换报名人，座位记录 `originalPlayerId`；
- 任何变动都触发全量重排，**锁座位次（桌号+座号）保持不动**；锁座导致无法均衡时阻断并提示先解锁。

### 积分与破同分（`computeStandings`）
- 独胜得胜局分、并列第一各得平局分、其余 0，处罚扣分；
- 排名并列时依次用：相互战绩 → 对手分（Buchholz）→ 游戏总分 → 处罚少者；
- 积分榜为**派生数据**：更正任意旧轮次赛果或追加处罚后立即全量重算，更正动作写入审计（含前后值）。
- 已结算轮的更正走**事务**：候选值必须重新满足整轮赛果规则——缺失比分/名次、负比分、零名次（或非 ≥1 整数）、名次断档都会阻断并整体回滚（旧赛果保留、不写审计、积分榜不变），页面输入框恢复原值。

### 状态机（`js/actions.js`）
- 轮次严格走 `草稿 → 已发布 → 已结算`，不能跳跃；只有已发布可撤销回草稿；只有草稿可删除；
- 已结算轮不能改出席/锁座/重排，只能更正赛果。

### 双页并发合并（`js/store.js`）
- 文档 `rev` + 实体 `rev`，本地基线/当前/远端三方合并：
  - 两边改不同实体 → 自动合流；
  - 同实体双改（含一删一改）→ 顶部冲突条逐条选择“保留本页 / 采用对端”，**绝不静默覆盖**；冲突未决期间存储保持对端版本。

### 导入导出
- 导出整库 JSON；导入前完整校验并出报告：
  - `DUPLICATE_ENTRY` 重复参赛者、`DUPLICATE_SEAT` 同桌同座号重复、`MISSING_FACTION` 悬空阵营引用（空阵营=中立，仅警告）、`BAD_SCORE` 非法比分/名次/断档、`MISSING_RESULT` 已结算轮缺比分或名次、`CYCLE` 补赛引用成环、`SCHEMA`/`DANGLING` 结构错误；
  - 已结算轮按结算同等标准校验（结果齐全、名次从 1 起且并列后顺延不断档）；草稿/已发布轮只校验已填值与座位结构；
- **任一硬错误即整体阻断，现有数据一行都不改**；校验通过后需再点一次“应用导入”才替换；审计日志跨导入保留。
